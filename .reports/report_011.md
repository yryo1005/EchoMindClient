# EchoMindClient Step 4: 常時録音

## 1. 概要

バックグラウンドで録音を続け，1時間ごとにファイルを区切って端末内に保存する常時録音の機能と，その状態を表示する録音タブを実装した．電話やSiri等による中断，入出力の経路の変化，メディアサービスのリセットの後は自動で録音を再開し，再開できない場合はローカル通知で知らせる．録音中にアプリが強制終了されても録音済みの音声を失わないよう，保存形式にはADTS形式のAAC(.aac)を採用した．シミュレーターで録音，強制終了，再起動後の復元を確認した．実機での確認は，Xcodeのアカウントの認証とiPhoneのデベロッパモードの設定が済んでいないため行えていない．あわせて，Step 3の確認として，会話タブ，人物タブ等に問題がなかったことを`report_010.md`に追記した．

## 2. 保存形式の選定

録音中のアプリは，メモリ不足によるシステムの終了やユーザーの操作によって強制終了され得る．そこで，`AVAudioFile`で書き込んだファイルを閉じずにプロセスを終了した場合に，ffmpeg(サーバーの音声の読み込みと同じ手段)で読み出せるかを3つの形式で比較した．音声は10秒の正弦波(16kHzモノラル，32kbpsのAAC)である．結果を表1に示す．

表1: 保存形式ごとのデコード結果(10秒の音声)

| 形式 | 正しく閉じた場合 | 閉じずに終了した場合 | 途中で切り詰めた場合 |
| :---: | :---: | :---: | :---: |
| m4a | 10.04秒 | 読めない(moov atomがない) | 読めない |
| caf | 読めない(パケットテーブルがない) | 読めない | 未確認 |
| aac(ADTS) | 10.18秒 | 9.98秒 | 切り詰めた位置まで(5.31秒) |

m4aはファイルを閉じる際に目次(moov atom)を書き込むため，閉じずに終了すると録音中のファイル全体が読めなくなる．1時間のファイルでは最大1時間の音声を失う．ADTS形式は短いフレームの連続で構成されるため，閉じずに終了しても，また途中で切り詰められても，それまでの音声を読み出せる．以上から，録音ファイルの形式をADTS形式のAAC(16kHzモノラル，32kbps，1時間あたり約15MB)とした．EchoMindServerはアップロードされたファイルの拡張子を保持してffmpeg経由で読み込むため，`.aac`も処理できると考えられるが，実際のサーバーでの確認はStep 5で行う．

## 3. 実装内容

### 3.1 録音ファイルの書き込み

`Services/RecordingFileWriter.swift`は，マイクの音声を`AVAudioConverter`で16kHzモノラルに変換し，`AVAudioFile`でADTS形式のAACとして書き込む．録音ファイルは最初の音声を受け取った時点で作成し，作成から1時間を超えると次のファイルに切り替える．入力の形式は経路(内蔵マイク，有線ヘッドセット等)によって変わるため，形式が変わった場合は変換器を作り直す．

EchoMindServerは発言の時刻を「録音開始時刻 + ファイル先頭からの経過時間」で求める．このため，1つのファイルの途中に録音の空白があると，空白より後の発言の時刻がずれる．そこで，録音の停止，中断，経路の変化のいずれでも，録音が止まる時点で必ずファイルを区切る設計とした．

書き込みは`AVAudioEngine`のタップ(オーディオ処理のスレッド)から，ファイルの区切りはメインスレッドから行われるため，内部の状態をロックで保護した．iOS 27では，タップの設置が`installAudioTap(onBus:bufferSize:format:tapProvider:)`に置き換わった．タップの処理は`@Sendable`となり，読み取り専用のバッファ`AVReadOnlyAudioPCMBuffer`を受け取る．このバッファを`AVAudioPCMBuffer(copying:)`でコピーして変換器に渡す．

### 3.2 ファイル名と保存先

`Services/RecordingStorage.swift`は，録音ファイルを`Application Support/Recordings`に保存し，iCloudバックアップの対象外とする．ファイル保護は既定の`completeUntilFirstUserAuthentication`であり，初回のロック解除後は画面ロック中でも読み書きできる．ファイル名は`rec_<録音開始時刻(UTC)>_<ID>.aac`(例: `rec_20261111T085352Z_1B70….aac`)とした．IDはサーバーへ送信する際の`client_file_id`である．強制終了によってデータベースに記録されなかったファイルも，ファイル名からIDと開始時刻を復元できる．年を桁数の指定なしで書き出すと，区切りのない数字列を解析できなかったため，4桁に固定した．

### 3.3 録音の制御と中断からの復帰

`Services/AudioRecorder.swift`は録音全体を制御する．音声セッションは`Services/AudioSessionManager.swift`で`.playAndRecord`に統一した．オプションは`.mixWithOthers`と`.defaultToSpeaker`である．`.mixWithOthers`により，他のアプリの音楽再生等で録音が中断されない．Step 3の発言音声の再生も同じ設定を用いるため，録音中に再生しても録音は止まらない．Bluetoothのヘッドセットのマイクは使用しない．AirPods等が低音質の通話モードに切り替わるのを避けるためである．

録音の有効・無効はUserDefaultsに保存し，アプリの起動時と前面に戻った時に，有効であれば録音を再開する．中断への対処を表2に示す．iOS 27では中断の通知(`AVAudioSession.interruptionNotification`)が非推奨となったため，`.didBecomeInactive`と`.resumptionRecommendation`のメッセージを用いた．

表2: 録音が止まる状況と対処

| 状況 | 検出方法 | 対処 |
| :--- | :--- | :--- |
| 電話，Siri等による中断の開始 | `.didBecomeInactive`(`systemInterruption`) | ファイルを区切り，中断中と表示する |
| 中断の終了 | `.resumptionRecommendation` | 再開の推奨の有無に関わらず再開を試みる |
| 入出力の経路の変化 | `AVAudioEngineConfigurationChange`(録音中にエンジンが停止した場合のみ) | ファイルを区切って再開する |
| メディアサービスのリセット | `mediaServicesWereResetNotification` | エンジンを作り直して再開する |
| 再開に失敗 | 再開後の状態 | ローカル通知で知らせ，アプリを開いた時に再開する |
| アプリの強制終了 | 次回起動時のファイルの一覧 | 記録されていないファイルを記録し，録音を再開する |

経路の変化の通知は，録音の開始時の設定変更でも届くことがあるため，録音中にエンジンが止まった場合のみ再開する．これにより，再開の処理が繰り返されることを防いだ．1秒未満または4KB以下の録音ファイルは会話を含み得ないため，記録せずに削除する．

### 3.4 録音タブ

`Features/Recording/RecordingView.swift`は，常時録音の切り替え，録音の状態(録音中の場合は書き込み中のファイルの経過時間)，保存した録音ファイルの一覧を表示する．一覧では各ファイルの期間，長さ，サイズを表示し，端末内での確認のために再生と手動での削除ができる．送信と送信後の削除はStep 5で実装する．

## 4. 動作確認

### 4.1 ビルド

Xcode 27.2の`xcodebuild`でiOSシミュレーター向けにビルドし，エラーと警告がないことを確認した．初回のビルドでは，iOS 27で非推奨となったAPI(`installTap`，`InterruptionType`)と，MainActorに隔離された定数の参照について警告が出たため，3.1節と3.3節で述べたAPIに置き換えて解消した．

### 4.2 録音ファイルの書き込み

`RecordingFileWriter`と`RecordingStorage`を確認用のプログラムと合わせてmacOS向けにコンパイルし，ファイルの切り替えを2秒に設定して，正弦波を0.1秒ずつ実時間で3秒間書き込んだ．途中で入力の形式を48kHzステレオから44.1kHzモノラルに変えた．保存先は確認用のディレクトリに切り替えた．確認した項目を表3に示す．

表3: 録音ファイルの書き込みの確認結果

| 確認項目 | 結果 |
| :--- | :---: |
| 書き込み中のファイル名を取得できる | 合格 |
| ファイルを区切った後は書き込み中のファイルがない | 合格 |
| 2秒で切り替わり，2つのファイルになる | 合格 |
| 1つ目のファイルの長さが約2秒(2.01秒)である | 合格 |
| 2つ目のファイルは1つ目の終了直後に始まる | 合格 |
| ファイル名からIDと開始時刻を復元できる(2ファイル) | 合格 |
| 規則に合わないファイル名を無視する | 合格 |
| 保存ファイルの一覧に2件が含まれる | 合格 |

初回の実行では，年を桁数の指定なしで書き出していたため，ファイル名から開始時刻を復元できず不合格となった．年を4桁に固定して解消した．作成したファイルはいずれもAAC，16kHz，モノラルであり，ffmpegでデコードできた．デコードした長さは，書き込んだ音声よりAACのエンコーダーの遅延(約0.13秒)だけ長くなった．macOSは26であり，iOS 27で追加された`AVReadOnlyAudioPCMBuffer`のコピーの処理は確認していない．

### 4.3 シミュレーターでの録音と強制終了からの復元

署名を有効にしてビルドしたアプリをiPhone 17のシミュレーターにインストールし，マイクの使用を許可して録音を有効にした状態で起動した．シミュレーターのマイクはMacのマイクである．時刻はUTCで記録した．

1. 08:53:51に起動すると，08:53:52に録音ファイルが作成され，3秒ごとに約4KB(32kbps相当)ずつ大きくなった．
2. 08:54:00にアプリを強制終了し，再び起動した．
3. 強制終了で閉じられなかったファイルが「08:53:52〜08:54:00，33,810バイト」として記録され，08:54:02から新しいファイルへの録音が始まった．

保存されたファイルは，強制終了で閉じられなかったものを含め，すべてffmpegでエラーなくデコードできた．デコードした長さ(6.7秒，24.3秒，8.5秒，17.8秒)は，記録した録音の長さとほぼ一致した．平均音量は-53〜-56dBであり，静かな室内の音が録音されていた．強制終了されたファイルの終了時刻はファイルの最終更新日時から求めるため，書き込みがまとめて行われる分，実際の終了より数秒早くなる場合がある．

確認の後，シミュレーターの録音を無効にした．このとき，設定ファイルを直接書き換えてもシミュレーターの設定のキャッシュ(cfprefsd)に古い値が残り，起動時に録音が再開した．シミュレーター内の`defaults`コマンドで書き込み直すことで録音が止まった．アプリの不具合ではないが，以降の確認で同じ方法を用いる場合は注意が必要である．シミュレーターには確認で録音した6件のファイルが残っている．

### 4.4 実機

接続されたiPhone 16 Pro Maxに向けたビルドは，iPhoneのデベロッパモードが無効であるため実行先として選べなかった．また，iOS向けの署名では，XcodeのアカウントのApple IDの認証が拒否されたこと，仮のBundle Identifier(`devplaceholder.S3YGLIV5.EchoMindClient`)のプロビジョニングプロファイルがないことにより失敗した．バックグラウンドでの録音，画面ロック中の録音，電話等による中断からの復帰は，実機でのみ確認できるため未確認である．

その後，ユーザーがデベロッパモードの有効化とXcodeのアカウントへのサインインを行った．Bundle Identifierを`com.yryo1005.EchoMindClient`に変更すると，プロビジョニングプロファイルが自動で作成され，実機向けのビルドが成功した．`devicectl`で実機にインストールできたが，開発元が信頼されていないため起動は拒否された．

ユーザーがiPhoneで開発元を信頼した後，実機で表3の項目を確認した．声が小さく環境音の方が大きく聞こえるという指摘については`report_012.md`で扱う．

表3: 実機での確認結果(ユーザーによる確認)

| 確認項目 | 結果 |
| :--- | :---: |
| 録音タブで常時録音をオンにできる | 良好 |
| ホームに戻る，画面をロックしても録音が続く | 良好 |
| 通話による中断の後に自動で再開する | 良好 |
| 強制終了して開き直すと，録音中だったファイルが一覧に追加される | 良好 |
| 1時間で録音ファイルが区切られる | 良好 |
| 録音を再生すると声が入っている | 声は入っているが小さく，環境音の方が大きい |
| AirPodsの装着中に録音すると，イヤホンから音が流れなくなる | 不具合(`report_012.md`で修正) |

## 5. 未解決の論点・次に検討すべき事項

- 実機での確認は表3のとおり完了した．再開できない場合の通知は，再開に失敗する状況を作れていないため未確認である．
- `.mixWithOthers`を指定した音声セッションで，バックグラウンドの録音が長時間維持されるかを実機で確認する必要がある．
- 電話の着信中に録音を再開できない場合，中断の終了を待つ間は録音されない．通話の内容は録音しない仕様で問題ないかを決める必要がある．
- 1時間の録音で端末のバッテリーとストレージの消費がどの程度になるかを実機で計測する必要がある．
- ADTS形式の`.aac`は，librosa 0.11では読み込めるが，librosa 1.0.0ではAAC全般を読み込めないことを確認した(`report_012.md`)．
- 稼働中のEchoMindServerは処理状況の確認API(`GET /api/upload/{upload_record_id}/status`)のない古いコードのままである．Step 5の前に最新のコードで再起動する必要がある．
- 次の作業はStep 5(Wi-Fi接続中かつ充電中の自動アップロードと，サーバーでの処理完了後の削除)である．

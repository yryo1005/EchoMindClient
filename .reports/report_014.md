# EchoMindClient 長時間の検証に向けた録音・送信のログ

## 1. 概要

Step 7(一晩の長時間の検証)に向けて，録音と送信の経過を端末に記録するログを実装した．録音ファイルは送信後に削除されるため，記録がないと，録音が途中で止まらなかったかを後から確認できない．ログはアプリの設定画面から確認でき，期間ごとの録音時間，録音の空白とその間に起きた出来事，バッテリー残量の推移を集計して表示する．ログのファイルは書き出すことができ，`devicectl`でMacに取り出すこともできる．試験(ログの読み書きと集計で14項目，送信の処理で31項目)はすべて期待どおりであった．実機にインストールしてログが記録されることを確認した．

## 2. 実装内容

### 2.1 記録する出来事

ログは`Services/EventLog.swift`が，JSON Lines形式(1行に1件)で`Application Support/Logs/events.jsonl`に追記する．各記録は，日時，種類，説明を持つ．録音ファイルの区切りの記録には，録音の区間，サイズ，区切った時点のバッテリー残量も付ける．記録する出来事を表1に示す．

表1: ログに記録する出来事

| 種類 | 出来事 |
| :--- | :--- |
| アプリ | 起動，前面への表示，バックグラウンドへの移行 |
| 録音 | 常時録音の有効化・無効化，録音の開始，開始の失敗，電話等による中断とその終了，録音が止まった際の再開とその失敗，本体のマイクを使えない間の一時停止と再開，1秒未満の録音の破棄 |
| ファイル | 録音ファイルの区切り(区間，サイズ，バッテリー残量)，強制終了などで記録されなかった録音ファイルの復元 |
| 送信 | 手動での送信の開始，送信(受付，処理中の重複)，サーバーでの処理の完了と削除(会話として保存，会話なし)，処理の失敗(回数)と自動での再送の中止，送り直し(処理が終わらない，記録が見つからない)，通信の失敗，送信の中止(ログインの期限切れ等)，Wi-Fi・充電の状態の変化，ログアウトによる録音の削除 |

録音は録音タブと同じ`AudioRecorder`，送信は`UploadManager`，アプリの状態は`MyApp`から記録する．タップのスレッドを含むどのスレッドからも記録できるよう，ファイルへの追記はロックで保護した．14日より古い記録は，アプリの起動時に削除する．1時間あたりの記録は数件から十数件(1件は約200バイト)であり，14日分でも1MB程度である．

### 2.2 集計と画面

`Services/RecordingTimeline.swift`は，ログの録音ファイルの区切りの記録から，指定した期間の録音を集計する．連続する2つの録音ファイルについて，前のファイルの終了から次のファイルの開始までが5秒を超える場合を，録音の空白とする．ファイルを区切る際の1秒程度の隙間は，空白に数えない．空白の間(前後2秒を含む)に記録された出来事は，原因の手がかりとして空白に添える．

`Features/Logs/EventLogView.swift`は，設定画面の「録音と送信のログ」から開く．表示する内容を表2に示す．

表2: ログの画面の表示内容

| 欄 | 内容 |
| :--- | :--- |
| 録音の集計 | 期間(24時間，3日，7日)の選択，録音ファイルの件数と合計サイズ，録音時間，空白の回数と合計時間，バッテリー残量の推移 |
| 録音の空白 | 空白ごとの期間，長さ，その間に起きた出来事(新しい順) |
| ログ | 種類(すべて，録音，ファイル，送信，アプリ)で絞り込んだログの一覧(新しい順，最大500件) |

画面右上のボタンで，ログのファイルを共有シート(AirDrop，ファイルへの保存等)から書き出せる．

### 3.2 実機

実機向けにビルドしてiPhone 16 Pro Maxにインストールし，起動した．その後，`devicectl`でログのファイルをMacに取り出した．取り出したログを表4に示す．インストールの際，録音中のアプリが終了したため，起動時にその録音ファイルが復元され，送信されたことが記録されている．

表4: 実機から取り出したログ(UTC)

| 日時 | 出来事 |
| :--- | :--- |
| 09:38:16 | アプリを起動しました． |
| 09:38:16 | 記録されていなかった録音ファイルを復元しました． |
| 09:38:16 | 録音を開始しました． |
| 09:38:16 | 充電を開始しました． |
| 09:38:16 | ネットワークの状態が変わりました(Wi-Fiに接続)． |
| 09:38:16 | アプリが前面に表示されました． |
| 09:38:16 | 11/12 18:23:07の録音を送信しました(受付)． |

起動直後の「充電を開始しました」と「ネットワークの状態が変わりました」は，起動時の状態の記録である．画面の表示はユーザーによる確認待ちである．

## 4. 未解決の論点・次に検討すべき事項

- Step 7として，一晩録音した後にログの画面で録音の空白とバッテリー残量の推移を確認する．あわせて，Macに取り出したログで送信と削除の経過を確認する．
- 録音中のファイル(区切られる前)は集計に含まれない．このため，直近の最大1時間は集計に表れない．
- アプリが強制終了されて復元した録音ファイルの終了時刻は，ファイルの最終更新日時である．そのため，強制終了の直前の数秒は区間に含まれない場合がある．
- 書き込みの途中でアプリが終了し，行が途中で途切れた場合，次の記録がその行に続けて書かれ，両方とも読めなくなる．記録は1行が小さく，起こる可能性は低いため，現時点では対処しない．
